# Workflow brief

Complete this with the person who performs the task today.

## 1. Outcome

- What should be true when the work is finished?
- Who uses the result?
- What does a correct result look like?

## 2. Trigger

- What event starts the process?
- Where can that event be detected?
- Can the same event arrive twice?

## 3. Volume and timing

- How often does the task occur?
- Are there peak periods?
- How quickly must the work finish?

## 7. Human approval

- Which actions require review before they happen?
- Who can approve them?
- What information must the reviewer see?
- What happens if nobody responds?

## 8. Systems and access

- Which apps, files or websites are involved?
- What is the smallest permission the workflow needs?
- Which system is the source of truth?
- How will credentials be stored and rotated?

## 9. Logging and privacy

- What must be recorded for troubleshooting?
- What must never be recorded?
- How long should logs be kept?
- How can a customer or employee request correction or deletion?

## 10. Pilot and rollback

- What sample data can be used safely?
- How many cases will the pilot run?
- What result ends or pauses the pilot?
- How can the old process be restored?
